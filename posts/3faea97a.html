Gromacs所使用的分子动力学模拟轨迹存储格式xtc，是一种压缩率较高的二进制格式，由于分子动力学模拟的轨迹本身就非常大，所以成倍数的压缩比可以极大程度上节约存储成本。

XTC分子轨迹存储格式的官方文档链接为：https://manual.gromacs.org/archive/5.0.4/online/xtc.html，其原文内容如下：

The xtc format is a portable format for trajectories. It uses the xdr routines for writing and reading data which was created for the Unix NFS system. The trajectories are written using a reduced precision algorithm which works in the following way: the coordinates (in nm) are multiplied by a scale factor, typically 1000, so that you have coordinates in pm. These are rounded to integer values. Then several other tricks are performed, for instance making use of the fact that atoms close in sequence are usually close in space too (e.g. a water molecule). To this end, the xdr library is extended with a special routine to write 3-D float coordinates. All the data is stored using calls to xdr routines.

int magic

A magic number, for the current file version its value is 1995.

int natoms

The number of atoms in the trajectory.

int step

The simulation step.

float time

The simulation time.

float box[3][3]

The The computational box which is stored as a set of three basis vectors, to allow for triclinic PBC. For a rectangular box the box edges are stored on the diagonal of the matrix.

3dfcoord x[natoms]

The coordinates themselves stored in reduced precision. Please note that when the number of atoms is smaller than 9 no reduced precision is used.

这是表示XTC文件的一个帧头结构，每一个时间戳的原子坐标数据，会被压缩进一个数据帧中。每一个数据帧的开头，就是如上述内容所示的帧头格式。

技术背景

分子动力学模拟（MD）以速度著称，所谓的速度，就是可以在更短的时间内，对更大的体系，做更长周期的连续采样。采样之后，要将样本点作为成果保存下来，这个轨迹数据，往往有比较大的分析价值，例如自由能分析等等。但是正因为分子模拟速度较快，产生的样本点也非常多，而且很多时候体系本身的体量就不小。那么如何更加高效的保存这些产生的数据，就成了一个需要解决的问题。Gromacs有一个比较成熟的方案，是使用比特流级别的压缩，将一个长轨迹压缩到逐帧的比特流中，极大程度上的节约了分子轨迹的存储空间。

轨迹压缩编码简析

上一个章节展示了xtc格式的压缩率，其实从图中也可以看出来，xtc用的是一个不等长的压缩算法。其大致的原理就是，假设前一个原子跟后一个原子的曼哈顿距离很近，那么就可以仅存储两个原子之间的坐标差值。因为其距离较小，所以坐标差值接近于0。而整体存储的数字越小，就可以用越少的比特数来进行存储。所以，XTC实际上使用了比特流级别的数据压缩算法。

总结概要

本文介绍了Gromacs的XTC格式的分子轨迹存储文件结构。每一帧的数据独立存储，帧头结构固定，数据帧则为不等长的比特流。这种采用精度可控的压缩算法，可以很好的适配各种不同场景的轨迹存储需求。
